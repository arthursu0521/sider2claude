日期：2026-11-01（北京时间）。分支：`fix/context-upload-diagnostics`。

## 基线与调查结论

用户提供的生产 Deno revision 为 `3ke3wrzt6m0n`，对应 Git 基线为
`c866566bd2b90d4da563e11670963318b260d0bc`。
开始工作时，本地 `main`、`origin/main` 缓存引用和 HEAD 均为这个提交；
`git log c866566..main` 与 `git diff --stat c866566 main` 均为空。
本轮没有查询远端最新引用，也没有将 main 的版本等同于部署状态。

已确认的是以下代码缺陷，不是生产故障的唯一根因：

1. 原 `sendText` 在 ACK 判定前保存新 `cid/parent`，上传序号稍后才另行保存。
   非 ACK、明确拒绝及两次写入之间的中断都可能留下不一致的检查点。
2. 多账号首次并发处理同一请求时，各自获得账号租约后，可能分别建档并发送。
   可控存储屏障稳定复现两次实际调用。
3. 新增具体错误码后，OpenAI 的 HTTP 和 Chat SSE 转换会丢失这些字段。
   原状态码、错误原因文字和 Retry-After 本来已能透传；此项不证明生产页面误报限流的根因。

未确认的生产原因，按当前调查优先级排列：

| 优先级 | 假设 | 支持证据 | 反证或限制 | 缺失证据 |
| --- | --- | --- | --- | --- |
| 1 | D：失败回复污染后续父节点 | 源码和 mock 均复现 ACK 失败后父节点前进 | 上传序号本身没有前进，首片也曾重试成功 | 生产检查点前后快照；Sider 对父节点分支的真实行为 |
| 2 | A：模型提前回答片段中的任务 | 第二片有 1163–1883 字符回复 | 长回复也可能是确认或拒绝 | 新诊断的 ACK 分类及授权后的模型复验 |
| 3 | E：切片或包装边界不清 | 按字符切割，头部指令后直接拼接原文，没有结束边界 | 现有明确 ACK mock 可以完整登记 | 原请求在真实模型上的对照实验 |
| 4 | C：拒绝正则误命中 | 拒绝词会匹配整个回复，可能命中引用或否定句 | 没有生产回复 fixture；明确拒绝必须保持优先 | 经单独授权获得的必要脱敏样本 |

ACK 分类仍是现有规则的判定结果，`explicit_rejection` 不等于已经人工确认模型真实拒绝。

## 实现与兼容影响

- 上传响应只累计用量；ACK 成功后，`cid/parent/uploads` 随同一个任务值一次保存。
  失败时保留上一个已确认父节点和 `pendingUpload`，停止后续发送。
  普通执行轮仍在收到完整上游结果后保存会话检查点。
- 选取账号前，用现有存储 `claim/release` 建立共享请求锁。
  锁按调用方、会话、规范化模型和原有重放请求语义隔离；流式开关不改变该身份。
  并发重复请求可能收到 429、Retry-After: 1，具体原因是 `controller_busy`。
  不同任务仍可使用不同账号并行；已有账号租约继续保护会话续轮。
- 保留 ACK 正则、拒绝优先、分片提示和运行时特有切片余量：
  Deno 为 `maxChars - 512`，Node/Bun 为 `maxChars - 256`。
- 分片未确认仍为 HTTP 502；登记检查点仍为 429；供应商 1135 仍为 429。
  SDK 依靠原登记进度文字的续传行为保留。
- Anthropic 在错误对象中新增可选 `error.code`；
  OpenAI 保留原 `error.type/code`，在可选 `error.details.code` 中携带具体原因。
  OpenAI Chat 已提交 SSE 的错误也保留此字段。
  本轮 HTTP 定向测试覆盖 Anthropic Messages 与 OpenAI Chat Completions。
- 机器码包括 `context_unconfirmed`、`context_checkpoint`、
  `controller_busy`、`sider_1135`；普通 502 不附带限流 Retry-After。
  已流出正文后失败继续输出明确错误事件，不发送成功结束事件。

**已有旧检查点的限制：**旧版失败时已经覆盖的父节点没有历史回退副本，
本次修改无法从现存记录自动推导它。修复防止后续新失败错误推进，
不会迁移或修改生产旧任务。若仍受旧状态影响，需要单独审查后选择新会话或恢复已知检查点。

## 默认安全诊断

新增结构化事件 `controller_context_upload`，包含：

- `requestId/requestHash/model`；
- `chunkIndex/chunkCount/contextHash`（contextHash 只取 SHA-256 前 16 位）；
- `responseChars/ack/ms`；
- `resumed/checkpointBefore/checkpointAfter`；
- 失败时的稳定 `code`。

ACK 分类为 `accepted / explicit_rejection / missing_ack`。
相同可选字段加入两套遥测类型；Deno 沿用现有有界 KV 遥测，
Node/Bun 的遥测持久化仍为原来的空实现，结构化日志两侧都有。

没有增加回复预览开关，也不输出 prompt、回复正文、用户正文、工具参数或凭证。
隐私测试把合成凭证、用户正文、历史工具参数、工具结果和回复回显分别放入请求/响应，
断言默认日志中均不出现这些值。所有测试使用合成数据和 mock，不访问真实上游。
